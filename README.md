# 깊은갱도 — 실시간 정체 은닉 웹 보드게임

원작의 리소스를 사용하지 않은 React + Express + Socket.IO 기반의 실행 가능한 프로젝트입니다. 게임 판정은 서버가 담당하며 공개 상태와 개인 상태를 분리합니다.

## 설치 및 실행

Node.js 22 이상을 권장합니다.

```bash
npm install
npm run dev
```

- PC 접속: `http://localhost:5173`
- 서버 상태 확인: `http://localhost:3001/api/health`
- 프로덕션 클라이언트 빌드: `npm run build`
- 프로덕션 실행: `npm run build && npm start` 후 `http://localhost:3001`
- 서버 규칙 테스트: `npm test`

## Docker 배포

Docker가 설치된 환경에서는 아래 명령으로 단일 컨테이너를 실행할 수 있습니다.

```bash
docker compose up --build -d
```

접속 주소는 `http://서버주소:3001`입니다. 운영 환경에서 웹 주소가 별도로 있을 때는 `.env`에 다음처럼 설정합니다.

```text
PORT=3001
CLIENT_ORIGIN=https://game.example.com
```

TLS(HTTPS)는 Nginx, Caddy 또는 클라우드 플랫폼의 리버스 프록시에서 처리하고, WebSocket 업그레이드를 허용해야 합니다. 여러 서버 인스턴스로 확장할 때는 Socket.IO Redis 어댑터와 공유 세션 저장소를 추가해야 합니다. 현재 버전은 단일 서버용 파일 저장소를 사용하며, 다중 인스턴스 동기화는 아직 지원하지 않습니다.

운영 환경에서는 `CLIENT_ORIGIN`을 반드시 실제 웹 주소로 설정하세요. 여러 주소가 필요하면 쉼표로 구분할 수 있습니다.

완료된 게임 기록은 기본적으로 `storage/game-history.json`에, 진행 중 방 상태는 `storage/room-state.json`에 저장됩니다. 운영 환경에서는 각각 `GAME_HISTORY_PATH`, `ROOM_STATE_PATH`를 영구 볼륨 경로로 지정할 수 있으며, 기본 Compose 설정은 `./storage`를 컨테이너에 연결합니다. 방 상태 복구 보존 시간은 `server/data/gameConfig.json`의 `roomStateRetentionMs`(기본 1시간)로 조절합니다.

## 멀티플레이 테스트

1. 첫 브라우저에서 닉네임을 입력하고 방을 만듭니다.
2. 초대 링크를 복사합니다.
3. 시크릿 창 또는 다른 브라우저 2개에서 링크를 열고 서로 다른 닉네임으로 참가합니다.
4. 참가자들이 준비한 뒤 방장이 게임을 시작합니다. 규칙상 시작에는 최소 3명이 필요합니다.
5. 각 창의 역할과 손패가 서로 다르며, 다른 참가자의 비밀 정보가 공개 상태에 포함되지 않는지 확인합니다.

## 같은 Wi-Fi의 모바일 테스트

PC와 휴대폰을 같은 Wi-Fi에 연결하고 PC 방화벽에서 Node.js의 개인 네트워크 접근을 허용합니다. PC에서 `ipconfig`(Windows) 또는 `ip addr`(Linux/macOS는 `ifconfig`)로 내부 IPv4 주소를 확인한 뒤 휴대폰에서 아래처럼 접속합니다.

```text
http://192.168.x.x:5173
```

Vite가 `/socket.io` 요청을 PC의 3001번 서버로 프록시하므로 모바일에서는 5173번 주소만 열면 됩니다.

## 주요 구조

```text
sabotaji/
├─ client/
│  ├─ src/components/       # 시작, 로비, 보드, 손패, 채팅 UI
│  ├─ src/App.jsx           # 공개/개인 상태 결합 및 화면 흐름
│  ├─ src/socket.js         # Socket.IO 요청 계층
│  └─ src/styles.css        # PC/모바일 반응형 디자인
├─ server/
│  ├─ data/                 # 규칙, 역할 수, 카드 구성, 보드 설정
│  ├─ src/game/             # 방, 게임, 보드 판정 엔진
│  ├─ src/index.js          # Express/Socket.IO 진입점
│  └─ test/                 # 보드 규칙 테스트
└─ package.json             # 워크스페이스 통합 실행
```

## 현재 구현

실제 기본판과의 차이, 검증 결과, 규칙 개선 우선순위는 [RULES_AUDIT.md](./RULES_AUDIT.md)를 참고하세요.

- 3~10인 방 생성/코드 참가/초대 링크
- 준비, 방장 시작, 실시간 채팅과 시스템 기록
- 재접속 토큰 및 5분 로비 유예
- 비밀 역할 개별 전송
- 데이터 기반 역할 비율, 손패 수, 터널 카드 수량, 초기 보드 배치 및 확장 정책
- 서버 전용 덱 순서와 목표 정체
- 턴 검증, 카드 소유권 검증, 버리기, 자동 뽑기
- 원작 기본 배치와 같은 5×9 초기 영역, 출발 카드, 숨겨진 목표 3개 및 목표 카드 경로 예외 처리
- 터널 회전/배치, 인접·벽 충돌·시작점 연결·중복 검증, 초기 영역 밖 확장 및 카드 내부 분리 통로 판정
- 목표에 길이 닿을 때 공개
- 선택→회전→칸 탭 방식, 보드 이동/휠 확대/중앙 복귀
- PC/모바일 반응형 UI, 모바일 채팅·대원 패널
- 선택형 턴 제한과 시간 초과 시 무작위 카드 자동 버리기
- 장비 고장·수리 행동 카드와 대상 선택
- 터널 카드 제거 행동 및 시작/목표 카드 제거 차단
- 숨겨진 목표 개인 확인과 개인 탐사 기록
- 실제 광맥 도달 시 탐사대 승리 서버 판정
- 덱과 손패 소진 시 교란자 승리 서버 판정
- 라운드 결과, 역할 전체 공개, 팀별 점수
- 여러 라운드 진행 및 방장 재경기 기능
- 재접속 토큰을 통한 역할·손패·장비·개인 탐사 기록 복구
- 연결 끊김/재접속 대기/장기 이탈 상태 표시
- 현재 차례 이탈 시 30초 뒤 서버 자동 처리
- 장기 이탈자의 손패 폐기 및 해당 라운드 제외
- 모바일 두 손가락 확대/축소, 한 손가락 보드 이동
- 카드 배치·목표 공개·현재 차례·승리 연출
- 브라우저 내장 음색 기반 효과음 토글
- 요청 형식·크기·빈도 검증과 운영용 헬스 체크
- Dockerfile, Compose, 환경 변수 예시
- 공개 대기실 목록과 새로고침
- 공개/비공개 방 선택, 비밀번호 방 생성·입장
- salt 기반 비밀번호 해시와 원문 비노출
- 장기 이탈 시 데이터 기반 AI가 합법적인 길·행동 카드만 선택해 게임 대행
- AI 대체 사용 여부 방 설정, AI 대행 중 재접속·다음 라운드 복귀 지원
- AI는 공개된 보드 연결망·장비 상태·턴 순서만 평가해 길 배치, 방해, 수리, 터널 제거를 선택
- AI 성향과 보드 평가 가중치는 `server/data/aiConfig.json`에서 조정 가능
- 기본판 인원별 역할 카드 풀·비공개 제외 카드, 0/180도 길 회전, 40장 길·27장 행동 카드
- 복합 수리 카드, 지도 카드 6장, 실제 금 조각 덱을 사용하는 비공개 보상 선택, 공동 최종 우승
- 매 라운드 서버가 무작위로 선택하는 첫 플레이어
- 완료 게임의 결과·점수 영구 저장, 닉네임 기준 누적 순위와 최근 게임 목록
- 진행 중 방 상태의 원자적 파일 저장 및 서버 재시작 후 재접속 토큰 기반 복구
